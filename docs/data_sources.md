## Data Access Architecture

The full connectome is NOT downloaded or loaded entirely into memory.
Server-side Cypher queries retrieve only the neurons and connections
that are requested by the application.

```
Full Dataset (neuPrint cloud)
        ↓
POST /api/custom/custom  (Cypher query)
        ↓
JSON response (columns + data rows)
        ↓
RealDrosophilaConnectomeProvider (normalization)
        ↓
Internal Neuron / Connection / SubgraphResponse models
        ↓
FastAPI endpoints
        ↓
Frontend
```

## Neuron Properties

The following node properties are queried from Neuron nodes:

| neuPrint field  | Internal field       | Notes |
|-----------------|----------------------|-------|
| `bodyId`        | `neuron_id`          | Integer, cast to str |
| `type`          | `cell_type`          | May be null |
| `instance`      | `instance`           | May be null |
| `superClass`    | `region` (proxy)     | Used as region proxy when no ROI filter |
| `status`        | `status`             | e.g., "Traced" |
| `predictedNt`   | `neurotransmitter`   | e.g., "acetylcholine" |
| `somaLocation`  | `x`, `y`, `z`        | [x,y,z] voxels (8 nm/voxel); absent for some neurons |

### Coordinate handling

`somaLocation` is a 3-element array in voxel space (8 nm/voxel).
When absent, `x`, `y`, `z` are set to `None` and `has_coordinates=False`.

**Coordinates are NEVER defaulted to `(0, 0, 0)` or any sentinel value.**
All downstream code (frontend and backend) must check `has_coordinates`
before using `x`, `y`, `z`.

## Provider Query Limits

To prevent unbounded queries against the large dataset:

| Operation                     | Server-side LIMIT |
|-------------------------------|-------------------|
| `get_neurons_by_cell_type`    | 100               |
| `get_neurons_by_region`       | 100               |
| `get_connections` (per neuron)| 250 out + 250 in  |
| `get_neighbors`               | 199 neighbors     |
| `extract_subgraph`            | 50 neuron IDs     |

## Authentication

All neuPrint endpoints require a Bearer token (JWT).

1. Sign in to https://neuprint.janelia.org with Google.
2. Copy your token from the Account page.
3. Set `NEUPRINT_TOKEN=<token>` in `.env` (never commit this file).
4. Set `CONNECTOME_PROVIDER=real` in `.env`.

---

## Synthetic Data (Development / Test)

The `SyntheticConnectomeProvider` is always available for development
and testing without any credentials.

Set `CONNECTOME_PROVIDER=synthetic` (or omit the variable entirely) to use it.
All neurons generated by the synthetic provider have `has_coordinates=True`
and deterministic positions derived from a fixed random seed.

**Synthetic data must never be confused with real biological data.**
The API, frontend header badge, and bottom bar all display the data source
identity clearly.
